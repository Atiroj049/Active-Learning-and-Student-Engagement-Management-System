## 2. ระบบของเรา

- **ระบบนี้ทำอะไร:** ระบบเว็บสำหรับบริหารกิจกรรมและการอบรมที่หลักสูตรวิศวกรรมซอฟต์แวร์รับผิดชอบ ครอบคลุมข้อมูลกิจกรรม การเชื่อมโยง PLO/CLO การลงทะเบียน การเข้าร่วม ชั่วโมง และ Reflection ผู้จัดหรือผู้ช่วยที่ได้รับสิทธิ์ตรวจหลักฐานและบันทึกการเข้าร่วมกับชั่วโมง ส่วนระบบจัดทำรายงาน PDF/XLSX และส่งชุดหลักฐานจากรายงานที่ผู้จัดตรวจรับรองแล้วให้ P1 ตาม IF05

- **ผู้ใช้หลักและผู้มีส่วนได้ส่วนเสีย:** ผู้ใช้หลัก ได้แก่ นักศึกษา อาจารย์ผู้จัดกิจกรรม และผู้บันทึกการเข้าร่วม โดยผู้จัดและผู้บันทึกอาจเป็นบุคคลเดียวกัน ผู้มีส่วนได้ส่วนเสีย ได้แก่ ผู้รับผิดชอบหลักสูตรและระบบส่วนกลางที่ใช้รายงานกับหลักฐานกิจกรรม

- **ผู้ใช้จริงที่จะชวนมาทำ UAT:** อาจารย์ผู้จัดกิจกรรม ผู้ช่วยที่ทำหน้าที่บันทึกการเข้าร่วม และนักศึกษาในหลักสูตร มีผู้ให้ข้อมูลเบื้องต้นแล้ว แต่ยังรอยืนยันผู้ตอบรับและนัดหมาย โดยเลือกงานทดสอบให้ตรงกับบทบาทจริง

- **การติดตั้งและทดสอบ:** ทดสอบเบื้องต้นบนเครื่องผู้พัฒนา แล้วเตรียมสภาพแวดล้อมให้ผู้ใช้ตัวแทนทดลองใช้งาน ส่วนเครื่องแม่ข่าย สเปกเครื่อง และสถานที่ติดตั้งใช้งานจริงรอยืนยันตาม TBD-04

ข้อตกลงที่ใช้ในการออกแบบและทดสอบ:

1. P5 ดูแลเฉพาะกิจกรรมที่หลักสูตรรับผิดชอบ กิจกรรมที่ต้องขออนุมัติจะดำเนินการภายนอกก่อนนำมาบันทึก ไม่รายงานซ้ำกิจกรรมที่มหาวิทยาลัยจัดและบันทึกในระบบของมหาวิทยาลัยอยู่แล้ว
2. ผู้มีสิทธิ์ตรวจหลักฐานและบันทึกการเข้าร่วมกับชั่วโมงได้ในกระบวนการเดียว โดยรวมยอดเฉพาะรายการที่ตรวจสอบครบ การลงทะเบียนหรือส่ง Reflection เพียงอย่างเดียวไม่ทำให้ได้รับชั่วโมง
3. การแก้ไขชั่วโมงใช้ค่าใหม่แทนค่าปัจจุบันโดยไม่นับซ้ำ พร้อมเก็บค่าเดิม ค่าใหม่ เหตุผล ผู้ดำเนินการ และเวลา
4. อาจารย์จัดเตรียมแหล่งข้อมูลบัญชีนักศึกษาและอาจารย์ให้ ส่วนวิธีตรวจสอบตัวตน เชื่อมข้อมูล และกำหนดสิทธิ์รอยืนยันตาม TBD-01
5. ผู้จัดกำหนดข้อความคำถาม Reflection **3 ข้อต่อกิจกรรม** นักศึกษาส่งหรือแก้ไขคำตอบได้ตามสิทธิ์และช่วงเปิดรับ
6. ผู้จัดตรวจรับรองรายงานก่อนส่งชุดหลักฐานให้ P1 หากข้อมูลต้นทางเปลี่ยน รายงานรุ่นเดิมคงเดิม และรายงานรุ่นใหม่ต้องผ่านการตรวจรับรองก่อนส่งต่อ
7. ยอดชั่วโมงใน P5 ครอบคลุมเฉพาะกิจกรรมที่มีข้อมูลในระบบ ไม่ใช่การรับรองชั่วโมงอย่างเป็นทางการ การออก Activity Transcript หรือการตัดสินการสำเร็จการศึกษา

## 3. เอกสารที่มีอยู่แล้ว

- **SRS:** ฉบับร่าง 0.1 วันที่ 25 พฤศจิกายน 2569 อยู่ที่ `docs/srs/SRS-T07_AUNQA_P5.docx`
- **จำนวนความต้องการ:** รวม **67 ข้อ** ประกอบด้วย FR 32 ข้อ, CFR 11 ข้อ, NFR 10 ข้อ และข้อกำหนดด้านข้อมูลกับส่วนต่อประสาน 14 ข้อ
- **RTM:** อยู่ใน SRS หัวข้อ 7 ตารางที่ 25 ครอบคลุมข้อกำหนดทั้ง 67 ข้อ โดยรหัสกรณีทดสอบเป็นรายการที่วางแผนไว้ ยังไม่ใช่ผลการทดสอบ
- **ข้อกำหนดคุณภาพและเกณฑ์ทวนสอบ:** อยู่ใน SRS หัวข้อ 6 ตารางที่ 24
- **แผนภาพปัจจุบัน:** C1 อยู่ในหัวข้อ 2.1, Use Case อยู่ในหัวข้อ 3.1 และแผนภาพสถานะรายงานอยู่ในหัวข้อ 3.5 ของ SRS
- **เอกสารออกแบบเพิ่มเติม:** C2 และ Activity Diagram มีร่างจากงานเดิมที่ต้องทบทวนให้ตรงกับ SRS ส่วน ER Diagram, Data Dictionary และ API spec ฉบับละเอียดสำหรับใช้พัฒนายังต้องจัดทำและระบุตำแหน่งใน repository

## 4. สถานะตอนนี้

- **Sprint ปัจจุบันและสิ่งที่กำลังทำ:** ยังไม่ได้ระบุหมายเลข Sprint อยู่ระหว่างทบทวนร่าง SRS เตรียมออกแบบรายละเอียด และยืนยันประเด็น TBD ที่เกี่ยวข้องก่อนพัฒนา
- **ส่วนที่จัดทำแล้ว:** มี SE02 ฉบับ 1.4 และร่าง SRS ฉบับ 0.1 พร้อมข้อกำหนด 67 ข้อ RTM ตารางสิทธิ์ และแผนภาพ C1, Use Case กับสถานะรายงาน โดยยังไม่ถือว่าได้รับการตรวจรับจากอาจารย์
- **สถานะการพัฒนา:** ยังไม่ได้ระบุความคืบหน้าของโค้ดใน Profile นี้
- **การทดสอบที่มีอยู่แล้ว:** มีรายการทดสอบและทวนสอบรายข้อใน RTM พร้อมเกณฑ์ยอมรับใน SRS แต่ยังไม่มีผลทดสอบระบบหรือ UAT แนบในเอกสารชุดนี้

ขอบเขตนำร่องประกอบด้วย **1 กิจกรรมและรายชื่อทดสอบอย่างน้อย 10 ราย** ส่วนการทดสอบการใช้งานใช้ผู้ใช้ตัวแทน **3 คน คนละ 3 งาน รวม 9 งาน ต้องสำเร็จอย่างน้อย 8 งานโดยผู้พัฒนาไม่ช่วย** รายชื่อทดสอบ 10 รายไม่ใช่จำนวนผู้ตอบรับ UAT

## 5. ส่วนที่ทีมคิดว่าเสี่ยงที่สุด 3 อย่าง

| ส่วนของระบบ | ทำไมคิดว่าเสี่ยง | ถ้าพังจะกระทบใคร อย่างไร |
|---|---|---|
| การยืนยันตัวตนและสิทธิ์เข้าถึงข้อมูล | ใช้แหล่งบัญชีที่อาจารย์จัดให้ และผู้ใช้คนเดียวอาจมีหลายบทบาท ต้องตรวจสิทธิ์ตามกิจกรรมและความเป็นเจ้าของข้อมูล ทั้ง API และไฟล์หลักฐาน | นักศึกษาและอาจารย์อาจถูกเปิดเผยข้อมูล หรือมีผู้แก้ไขการเข้าร่วมกับชั่วโมงโดยไม่มีสิทธิ์ |
| การบันทึกการเข้าร่วมและรวมชั่วโมง | การบันทึกซ้ำ การแก้ชั่วโมง และการรวมรายการที่ตรวจสอบไม่ครบอาจทำให้ยอดผิด ต้องใช้ข้อมูลปัจจุบันโดยไม่นับซ้ำและตรวจประวัติได้ | นักศึกษาอาจมีชั่วโมงเกินหรือขาด ผู้จัดต้องแก้รายงาน และหลักฐานของหลักสูตรอาจคลาดเคลื่อน |
| การนำเข้าและส่งหลักฐานกับระบบส่วนกลาง | รหัส รุ่นข้อมูล หรือรูปแบบแพ็กอาจไม่ตรงกัน การนำเข้าผ่าน API และไฟล์อาจให้ผลต่างกัน หรือเกิดข้อมูลซ้ำเมื่อนำเข้าใหม่ | หลักสูตรและ P1 อาจได้รับหลักฐานผิดกิจกรรม ไม่ครบ หรือซ้ำ รวมถึงได้รับรายงานรุ่นที่ยังไม่ผ่านการตรวจรับรอง |
